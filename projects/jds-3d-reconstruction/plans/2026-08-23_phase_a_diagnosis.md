# Phase A 诊断计划：确定退化是否存在、以及成因

> 前提：方向已定为「观测受限条件下的驾驶场景行人重建」，定位为 OmniRe 人体分支的改进工作。
> 本计划的目的**不是**证明方向成立，而是**尽早以最低成本证伪它**，并在证伪失败时确定方法形态。

## 设计原则

「存在 headroom」只是必要条件。真正决定方法的是**退化的成因**——不同成因指向完全不同的方法，其中一种还会把主贡献推离 3DGS 侧。

| # | 候选成因 | 若成立，方法应为 | 对一作的影响 |
|---|---|---|---|
| 1 | 信息不足：远处行人的像素数存在物理上限 | 先验注入 / 超分 | **不利**：主贡献推向人体先验侧 |
| 2 | 观测污染：差观测拉低好观测 | 观测加权与选择 | 有利，属 3DGS 侧 |
| 3 | 容量分配不当：远处行人分到的 Gaussian 过少 | 自适应容量分配 | 有利，属 3DGS 侧 |
| 4 | 姿态误差：远/遮挡时 SMPL 估计不准 | 姿态优化 | 不利，属人体先验侧 |
| 5 | **仅是训练分辨率设置** | —— | **选题不成立** |

Phase A 的每个实验都对应「如何分辨这些成因」。

## 实验

### E5 · 分辨率控制（`EXP-293A027FDD09`）

- **问**：退化是否仅由 `downscale_when_loading=3`（533×300）造成？
- **做**：scene 000 在默认分辨率与更高分辨率下各训练一次，其余配置严格一致。
- **得**：退化幅度对分辨率的敏感度。
- **判据**：高分辨率抹平远距分层的差距 → **成因 5，选题不成立，停止**。
- **风险**：原生 1600×900 六相机的显存需求未测。若需同时改动相机数或迭代数以适配显存，该实验将不再是单因素对照，其证伪强度相应下降，必须如实记录。

### E1 · 分层基线（`EXP-D364146FE7A6`）

- **问**：human-region 质量随观测条件如何退化？
- **做**：3 个行人密集场景（000/001/008，161 个行人实例）× OmniRe 默认配置；分层评测同时报告 coarse 与 fine 两种 human mask。
- **得**：12 格的 PSNR/SSIM 表与退化曲线；整体 human-region 值用于与论文的 28.15 / 24.36 对照量级。
- **判据**：最差格与最好格差距 **< 2 dB → 无 headroom，停止**。

### E2 · 观测级与实例级分解 · 零额外训练

本计划中信息价值最高的实验。

- **问**：信息能否跨帧转移，还是渲染分辨率即硬上限？
- **依据**：已测得 `best_view_visible_fraction` 的 p10 为 1.000——几乎每个行人都至少存在一个完全可见的视角。因此「同一实例在不同观测条件下的表现差异」是可测的。
- **做**：不训练。从 E1 的渲染结果按**观测**（frame × cam）而非按实例统计，分两组比较：
  - A 组「始终远」：最佳视角投影高度 < 32 px（渲染分辨率下），46 个实例；
  - B 组「曾经近」：最佳视角 > 107 px，57 个实例。
  比较 **B 组在其远帧上的表现** 与 **A 组在同等像素高度上的表现**。
- **判据**：
  - B 组远帧显著优于 A 组同等远帧 → **canonical 模型质量决定结果，信息可跨帧转移** → 成因 2/3，方法方向为观测聚合与利用；
  - 两组无显著差异 → **渲染分辨率为硬瓶颈** → 成因 1，方法须转向先验注入，且主贡献将推离 3DGS 侧。

### E3 · 高斯容量分配 · 零额外训练

- **问**：densification 给远处行人分配了多少 Gaussian？
- **做**：从 E1 的 checkpoint 读取每个 SMPLNode 的 Gaussian 数量，对分层作图。
- **判据**：远处行人的容量被显著压低 → 支持成因 3 与「观测充分性建模」这一技术核心。

### E4 · 观测选择的 oracle（Phase A 中唯一有工程量的实验）

- **问**：差观测是在帮助还是在损害重建？
- **做**：scene 000 三种训练——(a) 全部观测；(b) 只用可见比 > 0.8 的观测；(c) 只用像素高度最大的 K 帧。需改动 DriveStudio 的图像采样逻辑。
- **判据**：(b)/(c) 优于 (a) → 差观测有害，方法为加权与选择；(a) 最优 → 观测越多越好，方法为更好的聚合。
- **排期**：可在 E2 出结论后再决定是否执行。

## 执行顺序与止损

```
E5 ─┐
    ├─→ 高分辨率抹平差距 ──────→ 停，换题
E1 ─┘
    └─→ 最差与最好差距 < 2 dB ──→ 停，换题
              │
              ↓  （E2 / E3 由 E1 产物分析，零额外成本）
        方法方向二选一
              │
              ↓
             E4 → Phase B 方法设计
```

两个止损点均位于 Phase A 前半，总成本为 4 次训练。最贵的方法实现置于最后。

## 预注册

为避免事后挑选有利数字，以下在见到结果前固定：

- 分层定义为 `px_height_max` ∈ {<96, 96–160, 160–320, >320}（原生像素）× `visible_fraction_area_weighted` ∈ {<0.5, 0.5–0.8, >0.8}，12 格，各格实例数 46/65/59/57 与 71/63/93。
- E1 的 headroom 判据为最差格与最好格的 PSNR 差 ≥ 2 dB。
- E2 的分组阈值为渲染分辨率下 32 px 与 107 px（即原生 96 px 与 320 px）。
- 探索阶段每配置 1 个随机种子；任何进入论文主表的结论需 3 个种子并报告置信区间。
- 所有训练须经 `gpu-budget` 约束，并在结论中给出实测占空比；未给出实测值的运行不得声称施加了限制。

## 已知威胁

- nuScenes v1.0-mini 仅 10 个场景、227 个行人实例，其中 3 个场景贡献 71%。结论不能外推至 Waymo 或完整 nuScenes，须在论文中如实限定。
- 分层评测器与真实渲染输出的对接虽已通过代码核对，但尚未在实际产出的图像上验证。首次训练出图后须先核对文件数（19×6=114）与内容，再采信任何分层数值。
- SegFormer 掩码为替代实现，未与上游 mmseg 做逐像素比对（后者在本机无法运行）。
